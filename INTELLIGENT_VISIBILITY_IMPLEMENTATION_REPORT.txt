3. WHAT THE GUARD ACTUALLY CHANGES, MEASURED ON REAL DATA
--------------------------------------------------------------------------------

Before: `scripts/hide-confirmed-player-failures.py` removed an item from the
published payload purely on a NAME match against a browser-confirmation report.
No sibling route was considered, and no failure reason was examined.

The confirmation report records how many routes the player walked. Measured on
the live report:

  channel          distinct   plan    attempts   guard   why
                   sources    length  run
  ---------------- ---------- ------- ---------- ------- -------------------------
  Asian TV         1          1       1          HIDE    single source, plan
                                                         exhausted, non-vantage
  Bijoy Tv         1          3       3          HIDE    same
  Channel 1 NEWS   1          3       3          HIDE    same
  Channel 9        1          1       1          HIDE    same
  Desh TV          1          3       3          HIDE    same
  Drama 24         1          2       2          HIDE    same
  Ekattor TV       3          8       4          KEEP    plan abandoned at 4 of 8
  Ekhon Tv         2          7       4          KEEP    plan abandoned at 4 of 7
  EKUSHEY TV       1          3       3          HIDE    same
  Gazi TV          1          3       2          HIDE    same
  Global TV        1          3       3          HIDE    same
  Mohona TV        1          3       3          HIDE    same

  PROTECTED (now kept): 2       still allowed to hide: 10

Why "plan abandoned" blocks the hide: the report records COUNTS, never which
routes ran. A run that stopped at 4 of 8 attempts may have exercised one source
twice and never reached the third, so "every source was tried" cannot be
concluded. Both protected channels hold a backup marked verified_global.

Also blocked, by class rather than by count:
  * vantage-explainable failures (403 / 401 / 429 / 451 / geo / DNS /
    connect timeout) — the scanner sees a cloud egress, not a viewer's network.
    A published, owner-working channel was measured returning 403 three times
    from this vantage during the investigation.
  * transient failures (408 / 5xx / Cloudflare 520-527 / TLS / connection reset
    / mid-stream read timeout) — a single one of these is never a route fault.

Blocked decisions are written into the report as `kept_despite_confirmation`
with the reason, so nothing is silently dropped and nothing silently kept.

VISIBILITY INVARIANT: the guard only gates NEW removals. It does not un-hide the
231 existing ledger records (16 channels + 215 movies), and it does not newly
hide anything. Confirmed by `git diff -- data/` being empty.

4. REAL-BROWSER TEST ACROSS THE DECLARED TARGET MATRIX
--------------------------------------------------------------------------------

scripts/browser-target-matrix-check.py, run against a local server of the
modified site:

  profile           engine     result   checks
  ----------------- ---------- -------- --------
  desktop_chrome    chromium   PASS     6/6
  android_chrome    chromium   PASS     10/10
  iphone_safari     webkit     PASS     10/10
  android_tv        chromium   PASS     6/6
                                        32/32

Per-profile checks:
  * player script loaded
  * phone-size decision matches the profile (false for desktop and TV, true for
    the two phones) — this is the code path that special-cases TV user agents
  * no JS page error on load
  * compact bar: no overlapping controls
  * rotate / picture-in-picture never shown for a movie
  * centre tap-to-resume overlay suppressed
  and additionally on the phone profiles:
  * compact bar has no opaque backdrop
  * fullscreen bar: no overlapping controls
  * fullscreen bar keeps an exit control
  * fullscreen bar exposes volume and resolution

A REAL BUG THIS TEST FOUND (and it was mine):
  On Android Chrome in PORTRAIT with fullscreen active, the transport overlapped:
      movieLockBtn/muteBtn, muteBtn/skipBackBtn, skipFwdBtn/qualityBtn,
      qualityBtn/aspectBtn, aspectBtn/fullscreenBtn
  Cause: the fullscreen grid is 11 columns inside `@media (max-width:980px)`
  with no width floor, while the control sizing was fixed at 42px. On a 412px
  viewport each column is ~37px, so every 42px button overflowed its cell.
  My earlier harness only ever tested landscape (915x412), so it never saw this.
  Fix: a narrow-viewport block (max-width:560px) sizes the fullscreen controls
  to 28px (play/pause 38px) so 11 of them fit the narrowest supported viewport.
  Landscape proportions are unchanged. Re-tested: 0 overlaps on all profiles.

Scope stated honestly: this verifies initialisation, the phone-size decision and
control geometry. It does NOT perform the 120 s sustained-playback acceptance
defined in `classify_playback()`. That needs a machine able to decode video for
two minutes; this container has very little free RAM and a 64 MB /dev/shm, and
headless playback crashed repeatedly during the investigation. The floors are
implemented and unit-tested, but no channel has been given a real 120 s PASS.

6. WHAT IS IMPLEMENTED VS WHAT REMAINS
--------------------------------------------------------------------------------

IMPLEMENTED AND WIRED INTO PRODUCTION
  * the browser-confirmation guard on the real hide path
  * the narrow-viewport fullscreen fix
  * the whole model as a tested library

IMPLEMENTED AS A LIBRARY, NOT YET WIRED
  `may_hide()`, `classify_playback()`, `resolve_verdict_scope()`,
  `independent_redundancy()`, the HMAC identity fields and the three-state
  policy are complete and tested, but they are not yet consumed by the scanner's
  other hide paths (`verifier.py`, `bd_verifier.py`, `browser_reachability.py`).
  Those paths were left alone deliberately: they are large, they run on every
  scan, and rewiring them without a 120 s acceptance harness would risk exactly
  the channel loss this work exists to prevent. They remain the next step.

NOT DONE, AND WHY
  * No 120 s sustained-playback acceptance was run (container cannot decode
    video for two minutes). No channel has therefore been PROVEN, and none has
    been promoted.
  * No HMAC key exists in CI, so every HMAC field is unavailable and any record
    built today is `unknown` by the schema's own rule. That is the correct
    behaviour, not a workaround.
  * Vantage independence remains measured-once, not established. The worker-path
    egress did not echo on the final attempt.
  * The two HEVC channels (beIN SPORTS 1, BEIN SPORTS 6) cannot be fixed here
    for a browser without HEVC support. Their HEVC keyframes are fine; the
    tested browser is the limitation, so they stay environment-scoped advisory
    and are never hidden globally.


--------------------------------------------------------------------------------
7. HONEST NOTES
--------------------------------------------------------------------------------

  * The Android Chrome portrait overlap was a regression I introduced earlier in
    this session and did not catch, because my own harness only tested
    landscape. The 4-profile matrix caught it. That is the whole argument for
    testing the declared matrix rather than one profile.
  * The guard is deliberately narrower than the full `may_hide()` bar. Requiring
    two independent vantages would stop every hide until new infrastructure
    exists; instead the guard blocks only the cases where the evidence provably
    cannot justify removal. A genuinely dead single-source channel can still be
    hidden.
  * This repository is PUBLIC and data/channels/*.json already contains
    credential-bearing stream paths for other channels. Nothing here adds to
    that exposure, and nothing here removes it. It remains the owner's call.
  * No claim of "100% never buffering on every network" is made anywhere.
