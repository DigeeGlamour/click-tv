মূল সিদ্ধান্ত (আপনার Option C)
--------------------------------------------------------------------------------
ম্যাচ শুরুর ৩০ মিনিট আগেই Today Match-এ চলে আসবে।

কেন এটা ঠিক:
  ৭:৪৫-এ সাইট খুলে "Today Match" চাপলে ৮টার ম্যাচ নেই — এটা সত্যিকারের ভুল।
  নাম বদলে ("Live Now") সেটা সারে না। এটা নাম নয়, আচরণ ঠিক করে।
  আর Upcoming-এ ২১০টা, Today-তে ২৭টা — যেগুলো এখনই দরকার সেগুলো Today-তে
  এলে দুটো tab-ই নিজের কাজটা করবে।

নতুন প্রবাহ:
  ৩০ মিনিটের বেশি বাকি  →  Upcoming
  ≤ ৩০ মিনিট বাকি       →  Today Match  🟡 শুরু হবে ২৮ মিনিট পর
  link পাওয়া গেল        →  Today Match  🟢 stream প্রস্তুত • ১২ মিনিট পর
  শুরু হয়ে গেছে         →  Today Match  🔴 LIVE
  শুরু হয়েছে, link নেই   →  Today Match  🟠 link খোঁজা হচ্ছে
  ৩০ মিনিট পরেও link নেই →  বাদ

  Upcoming → Starting Soon → Live Now → Ended
  card কোথাও অদ্ভুতভাবে লাফাবে না।

[✅ শেষ]  ১. খোঁজার জানালা ২০ → ৩০ মিনিট
--------------------------------------------------------------------------------
    কেন ৩০: routing threshold-ও ৩০। ২০ থাকলে card ৩০ মিনিটে Today-তে আসত
    কিন্তু link খোঁজা শুরু হত ১০ মিনিট পরে — ওই ১০ মিনিট card বসে থাকত।

      "Targeted window: -30 minutes; targets=3, outside window=207"


[✅ শেষ]  ২. Routing — ৩০ মিনিট বাকি থাকতেই Today Match-এ
--------------------------------------------------------------------------------
    এখন: STARTING_SOON আর LINK_UPDATING → Upcoming
    হবে : সময় ≤ ৩০ মিনিট হলে status যাই হোক → Today Match

    গুরুত্বপূর্ণ: এখনকার targeted_window_minutes শুধু "link খোঁজার" জানালা,
    tab routing-এর নিয়ম নয়। তাই routing-এর জন্য আলাদা নিয়ম লাগবে।

    করা হয়েছে: scanner/event_lifecycle.py → event_destination()
    ঘড়ি ধরে যাচাই (৮টার ম্যাচ):
      ৫:০০ PM → Upcoming    ৭:৩০ PM → Today Match
      ৭:০০ PM → Upcoming    ৭:৪৫ PM → Today Match
      ৭:২৯ PM → Upcoming    ৮:০০ PM → Today Match

    ⚠️ এটা করতে গিয়ে আমার নিজের একটা bug ধরা পড়ল:
       link ছাড়া card Today-তে এসে "চালানো যায় না" বলে পুরোপুরি মুছে যাচ্ছিল।
       প্রথম run-এ ৬টা card দুই tab থেকেই হারিয়ে গিয়েছিল
       (Raków Częstochowa vs Jagiellonia সহ)।
       এখন schedule card হিসেবে থাকে — Upcoming-এ যেভাবে থাকত।
       Pages validator-ও এখন Today-তে metadata card মেনে নেয়।

    আসল scan-এ প্রমাণ: ৩১টা card, তার ২টা এখনো শুরু হয়নি —
      "শুরু হবে ২৪ মিনিট পর  Raków Częstochowa vs Jagiellonia  link=False"
      "শুরু হবে  ৯ মিনিট পর  Day 4 vs The K Club (2026)        link=False"


[✅ শেষ]  ৩. Today card-এ status + countdown
--------------------------------------------------------------------------------
    ⚠️ এখানে আমার আগের পরামর্শ উল্টে যাচ্ছে, সেটা লিখে রাখলাম।

    আমি বলেছিলাম "Today-তে সবই live, তাই badge আবর্জনা"।
    কিন্তু Today-তে এখনো শুরু না হওয়া ম্যাচ ঢুকলে status ছাড়া card
    মিথ্যা বলবে — দেখতে live লাগবে, আসলে নয়। তাই এখন লাগবেই।

      🔴 LIVE
      🟡 শুরু হবে ১২ মিনিট পর
      🟠 link খোঁজা হচ্ছে

    করা হয়েছে: app.js → todayCardState()  +  event-channel-cards.css
    চারটে অবস্থা:
      🔴 LIVE                              চলছে
      🟢 স্ট্রিম প্রস্তুত • ১২ মিনিট পর     link আছে, শুরু হয়নি
      🟡 শুরু হবে ২৪ মিনিট পর               link নেই, শুরু হয়নি
      🟠 লিংক খোঁজা হচ্ছে                   সময় হয়ে গেছে, link নেই


[✅ শেষ]  ৪. Today-র ভেতরে সাজানো

    নইলে না-শুরু-হওয়া ম্যাচ চলতি ম্যাচের উপরে বসবে।


[✅ শেষ]  ৫. Header-এর লেখা

    হয়েছে: শিরোনাম "31 Matches", পাশে detail-এ "5 Live • 31 Matches"

[✅ শেষ]  ৬. link না এলে বাদ দেওয়া
--------------------------------------------------------------------------------
    শুরুর ৩০ মিনিট পরেও কোনো source link না দিলে Today থেকে বাদ।
    তার বেশি রাখলে Today-ও আবর্জনায় ভরবে।

    (এখনকার নিয়ম ১০ মিনিট, কিন্তু সেটা Upcoming থেকে বাদ দেওয়ার নিয়ম।
     নতুন system-এ card তখন Today-তে থাকবে, তাই নিয়মটা সরাতে হবে।)


[✅ শেষ]  ৭. Upcoming-এর sort — যেটা আগে শুরু হবে
--------------------------------------------------------------------------------
    এখন যা হচ্ছে:
      ৫ মিনিট পরে football   ← নিচে
      আগামীকালের cricket     ← উপরে

    কারণ কোডে sportRank সময়ের আগে চলে (app.js line ~1841)।

      Upcoming → যেটা আগে শুরু হবে (সময়ই এখানে একমাত্র যুক্তি)


[✅ শেষ]  ৮. মোবাইলে tap target ২৫px → ৪০px
--------------------------------------------------------------------------------

    সাবধানে: ২ column grid-এ button বড় করলে জায়গা কমে।
    তাই ৪২০px-এর নিচে channel strip এক column — লেখা আরও ছোট করার চেয়ে।

    করা হয়েছে: ২৫px → ৪০px, ৪২০px-এর নিচে এক column (৪২px)


[✅ শেষ]  ৯. এক-channel card-এ channel-এর নাম

  ১. আসল browser-এ পুরো যাচাই
     Cloudflare deploy হওয়ার পর — card-এর badge, countdown, sort, মোবাইলে
     button-এর মাপ চোখে দেখে মিলিয়ে নেওয়া। এখনো করা হয়নি।

  ২. GitHub-এর scan কত ঘন ঘন চলছে
     cron সরানো হয়েছে (:০৩/:২৩/:৪৩ আর :০১/:০৬/:১১), concurrency দুই ভাগ
     করা হয়েছে — কিন্তু ফাঁক সত্যিই কমেছে কিনা তার সংখ্যা এখনো হাতে আসেনি।
     GitHub-এর scheduler আমার হাতে নেই, তাই browser-এর ঘড়ি-নিয়মই ভরসা।

  ৩. আটকে থাকা ৬টা queued run
     মোছা যাচ্ছে না (token-এ শুধু metadata=read, তিনটে API-ই 403)।
     কিন্তু কিছু আটকাচ্ছেও না — ওরা পুরোনো `live-signal-data-writer` group
     ধরে আছে, এখনকার run গুলো `-v4` group-এ। প্রমাণসহ ফাইলে লেখা আছে।

  ৪. HIGH-1-এর যুক্তিটা (audit)
     একটা `status` field দিয়ে দুটো কথা বলা হচ্ছে — "ম্যাচ শুরু হয়েছে" আর
     "stream চালু"। এখনকার ডেটায় কোনো ভাঙা জিনিস নেই, তাই ছোঁয়া হয়নি।
     ভবিষ্যতে আলাদা করলে ভালো হবে।
