১. সহজ ভাষায় চূড়ান্ত সিদ্ধান্ত
================================

Zee Bangla আটকে যাওয়ার প্রধান কারণ আপনার internet speed কম হওয়া নয়। বর্তমান Zee Bangla source এবং browser playback পদ্ধতির মধ্যে একাধিক প্রমাণিত সমস্যা আছে:

১) Channelটি normal HLS (.m3u8) নয়; raw MPEG-TS (.ts) source ব্যবহার করছে।

২) Sourceটি continuous live connection হিসেবে খোলা থাকছে না। অল্প কিছু media একবারে পাঠিয়ে connection বন্ধ করে দিচ্ছে।

৩) Direct source test-এ ২৫ সেকেন্ড media পাওয়া গেছে, কিন্তু response প্রায় ২.৬৫ সেকেন্ডেই সম্পূর্ণ শেষ হয়ে গেছে।

৪) Click TV production proxy দিয়ে একটি captured response-এ মাত্র ৭.৩ সেকেন্ড media পাওয়া গেছে; এরপর response শেষ।

৫) Captured direct ও proxy video—কোনোটিতেই একটিও H.264 IDR keyframe পাওয়া যায়নি। IDR হচ্ছে এমন একটি পূর্ণ keyframe যেখান থেকে decoder নিরাপদে নতুন করে picture তৈরি শুরু করতে পারে।

৬) Full Chrome browser test-এ দুই proxy attempt-এই MEDIA_ERR_DECODE হয়েছে। ৫০ সেকেন্ড test-এ video currentTime ০ সেকেন্ড থেকে একবারও সামনে যায়নি।

৮) Scanner মাত্র ১৬ KB valid media sample পেলেই channel-কে Verified বলছে। এটি long-time smooth playback, keyframe বা connection continuity প্রমাণ করে না।

৯) Player recovery একই loaded mpegts.js player-এ আবার load() call করছে। mpegts.js 1.7.3 এই অবস্থায় দ্বিতীয় load() গ্রহণ করে না; exception-টি empty catch-এর কারণে দেখা যায় না।

১০) Latest buffer patch production-এ আছে, কিন্তু buffer বাড়িয়ে missing keyframe, finite response এবং missing backup ঠিক করা সম্ভব নয়।


২. ব্যবহারকারীর device-এ কীভাবে সমস্যা দেখা দিতে পারে
====================================================

সম্ভাব্য playback chain:

IDR keyframe ছাড়া raw TS snapshot শুরু
→ decoder পুরোনো reference frame না পেয়ে decode delay/error করে
→ কোনো tolerant device picture দেখাতে পারলেও বারবার recover/conceal করতে হয়
→ short media burst শেষ হয়
→ buffer ফাঁকা হয়ে যায়
→ waiting/stalled/ended event আসে
→ recovery কার্যকরভাবে reconnect করতে পারে না
→ অন্য proxy দিয়ে একই origin আবার চেষ্টা হয়
→ video থামে, আবার চলে, আবার থামে; অথবা সম্পূর্ণ বন্ধ হয়ে যায়।

এই কারণে কোনো device-এ “আটকে আটকে” চলতে পারে, আবার Chrome-এর মতো অন্য environment-এ একেবারেই play নাও হতে পারে। দুইটি symptom-এর source-level কারণ একই।

১১. সঠিক সমাধানের priority
==========================

Priority ১ — Current source বদলানো

Zee Bangla-এর জন্য stable HTTPS rolling HLS master/media playlist খুঁজে sustained test করে primary করতে হবে। HLS-এর ছোট independent segment, rolling sequence, retry এবং adaptive bitrate browser-এর জন্য raw single TS response-এর চেয়ে নির্ভরযোগ্য।

পুরোনো history থেকে URL copy করে সরাসরি ব্যবহার করা যাবে না:

- একটি historical ottplus URL test-এ 403 দিয়েছে;
- report-এ অন্য Zee source 404 আছে;
- Toffee hostname diagnostic location থেকে resolve হয়নি।

নতুন candidate current test pass না করলে publish করা যাবে না।

Priority ২ — আসল backup যোগ করা

কমপক্ষে দুইটি different upstream/provider/host-এর independently verified source রাখতে হবে। একই playback ID-এর Proxy 1 এবং Proxy 2 independent backup নয়। Final channel data-তে available_link_count কমপক্ষে ২ এবং backups non-empty হতে হবে।

Priority ৩ — Scanner continuity/keyframe gate

Live raw MPEG-TS-এর জন্য:

- ১৬ KB sample দিয়ে verified দেওয়া বন্ধ করতে হবে;
- production proxy দিয়ে কমপক্ষে ৬০ সেকেন্ড test করতে হবে;
- timeout-এর আগে clean EOF হলে fail করতে হবে;
- PCR/PTS নিয়মিত সামনে যাচ্ছে কি না দেখতে হবে;
- TS sync ও continuity counter দেখতে হবে;
- strict startup window-এর মধ্যে IDR/independently decodable keyframe থাকতে হবে;
- codec browser-compatible কি না দেখতে হবে;
- result report-এ duration, bytes, bitrate, EOF reason, keyframe delay ও proxy লিখতে হবে।

Priority ৪ — Raw MPEG-TS থাকলে player recovery ঠিক করা

- mpegts.Events.LOADING_COMPLETE শুনতে হবে;
- loaded player-এ দ্বিতীয়বার load() call করা যাবে না;
- pause → unload → detach → destroy → নতুন player create → attach → load → play sequence দরকার;
- retry সংখ্যা সীমিত রাখতে হবে;
- error log লুকানো যাবে না;
- retry fail হলে সত্যিকারের independent backup-এ যেতে হবে।

এটিও gap পুরোপুরি দূর করবে না। Client reconnect temporary damage control; stable HLS source হলো ভালো সমাধান।

Priority ৫ — HLS source না থাকলে server-side repackaging

একটি stateful FFmpeg/GStreamer relay দিয়ে upstream continuously ingest করে rolling HLS segment বানাতে হবে। Stateless Cloudflare Worker শুধু response.body pass-through করে finite snapshot-কে seamless continuous stream বানাতে বা incompatible media transcode করতে পারে না।

- MediaMSEError
- MEDIA_ERR_DECODE / video error code 3
- fatal network/media error
- নিজে থেকে route/attempt change
- playback plan exhausted

৯) CI/diagnostic artifact হিসেবে machine-readable event timing সংরক্ষণ করতে হবে। শুধু HTTP 200, screenshot অথবা ৫ সেকেন্ড play proper proof নয়।
