২.২  Bare IP — যে route কোনোদিনও কোনো দর্শকের কাছে পৌঁছাতে পারে না
--------------------------------------------------------------------------------
commit fbb83bceb  |  scanner/deliverability.py  |  13টা নতুন test

Cloudflare-এর fetch() সরাসরি IP ঠিকানায় যেতে অস্বীকার করে। Edge নিজেই 403
দেয়, body-তে `error code: 1003`, request Cloudflare ছাড়ার আগেই।

লাইভ worker-এর বিরুদ্ধে, সাইটের নিজের Origin দিয়ে, তিনটে সম্পর্কহীন ঠিকানায়
মাপা (তিনটেই আগে থেকেই host allowlist পার করা ছিল):

      http://181.119.215.61:8000/...   Disney Channel  -> 403 error code: 1003
      http://23.237.104.106:8080/...   Dazn 2, 4, 5    -> 403 error code: 1003
      http://66.102.126.10:8000/...    Star Gold       -> 403 error code: 1003

একই run-এ নাম-ওয়ালা host একই proxy দিয়ে 200 আর পড়ার যোগ্য manifest দিয়েছে।
অর্থাৎ দোষ IP literal-এর, আর কিছুর নয়।

এর কোনো বিকল্প পথ নেই: সাইট HTTPS, তাই http:// stream সরাসরি video element-এ
দেওয়া যায় না (mixed content), তাই proxy-ই একমাত্র পথ, আর proxy-ই অস্বীকার করে।
https:// bare IP এক ধাপ পরে মরে — certificate নামের জন্য ইস্যু করা।

      পাওয়া গেছে : ৬টা channel route + ৫৯টা event backup — প্রত্যেকটা "Verified"
      কোনো card হারায়নি : ৪টা primary-র জায়গায় backup বসেছে, ৫৯টা backup বাদ

  Verifier এখন network call করার আগেই এগুলো ফেরত দেয়। Pages validator-ও
  আটকায়, যাতে অন্য দরজা দিয়ে (manual entry, fixup script, promotion) আর ঢুকতে
  না পারে।

commit fdf810be2  |  10টা নতুন test

reports/bd-verification.json redactor ছাড়াই ডিস্কে লেখা হত। একমাত্র সুরক্ষা
ছিল query-string strip — যা `?hdnts=...` ধরে, কিন্তু এই প্রজেক্ট আসলে যে দুটো
রূপের সাথে কাজ করে সেগুলো ধরে না:

      https://host/live/hdntl=exp=...~hmac=<64 hex>/index.m3u8   (path-এর ভেতর)
      __hdnea__=st=...~exp=...~hmac=<64 hex>                     (cookie)

এই ফাইল প্রতিটা scan-এ একটা public repository-তে commit হয়। একটা token বেরিয়ে
গেলে ফেরানোর উপায় নেই। এখন report redactor-এর ভেতর দিয়ে যায়, আর redactor
এখন নাম আর আকার — দুটো মিলিয়ে token ধরে, যাতে "key" বা "expires" শব্দওয়ালা
সাধারণ লেখা নষ্ট না হয়।
