রাখে। এখানকার কোনো কোড দিয়ে GitHub-কে সেটি মানানো যাবে না। (queue time মাপা
হয়েছে: প্রতিটি run-এর queue_s = 0, অর্থাৎ run আটকে নেই — তৈরিই হচ্ছে না।)

যে run-গুলো টিকে যায় তারা কী করবে, সেটি আমাদের হাতে। পুরোনো নিয়মে প্রতিটি run
শুধু নিজের cron-এর mode চালাত, তাই ঘন cron দুটি অল্প slot দখল করে নিত এবং বাকি
mode-গুলো একেবারেই চলত না:

    channels  cron 17 0,6,12,18  →  শেষ আসল scan 2026-08-28 22:44 UTC (১৬.২ ঘণ্টা পুরোনো)
    movies    cron 37 4          →  শেষ আসল scan 2026-08-27 15:13 UTC (৪৭.৭ ঘণ্টা পুরোনো)

দুটোই তখনো site-এ publish হচ্ছিল।

সমাধান (scripts/select-scan-mode.py + workflow-এ একটি step): টিকে যাওয়া run
তার নিজের mode-এর পাশাপাশি যে catalogue mode overdue, সেটিও চালাবে। যোগ করে,
প্রতিস্থাপন করে না; manual dispatch-এ কখনো নয়; এক run-এ একটির বেশি নয়; আর সীমা
